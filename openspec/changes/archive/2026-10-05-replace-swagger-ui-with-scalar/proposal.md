# Proposal

## Why

The API docs page at `/api/v1/docs` is the default Swagger UI, which is dated and hard to navigate for a growing API (six modules, role-gated endpoints). Scalar renders the same OpenAPI document with a modern layout, search, per-endpoint request examples and a built-in client, so frontend developers can explore and try the API without extra tooling.

## What Changes

- Serve the API reference at `/api/v1/docs` with Scalar (`@scalar/nestjs-api-reference`) instead of Swagger UI.
- Keep the OpenAPI document generated by `@nestjs/swagger`; expose it as JSON at `/api/v1/docs-json` so tools and clients can still consume it.
- Give the docs route its own `Content-Security-Policy` with a per-request nonce, because Scalar loads its bundle from `cdn.jsdelivr.net` and initialises through an inline script that helmet's default CSP blocks. Every other route keeps helmet's default CSP.
- Update the docs that mention Swagger UI: `README.md`, `docs/API.md`, `CLAUDE.md`.
- No endpoint, DTO, auth, or business-rule change.

## Capabilities

### New Capabilities
- `api-reference-docs`: where the interactive API reference and the raw OpenAPI document are served, that they are publicly reachable, and the scoped CSP the docs page requires.

### Modified Capabilities

None. `security-headers` still holds: the docs response carries a `Content-Security-Policy`, and that spec does not fix its value.

## Impact

- **Code**: `src/main.ts` (docs setup). No use case, controller, repository or schema change.
- **Dependencies**: adds `@scalar/nestjs-api-reference`. `@nestjs/swagger` stays (it builds the OpenAPI document).
- **Runtime**: the docs page loads the Scalar bundle from `https://cdn.jsdelivr.net` in the browser, so viewing it needs internet access.
- **Docs**: `README.md`, `docs/API.md`, `CLAUDE.md`.
- **Reference**: a working draft exists on branch `draft/scalar-api-reference` (commit `9f142a5`).

## Security Considerations

- **Client-writable fields**: none added.
- **Who can reach it**: the docs page and the JSON are public, as the Swagger UI was. They are registered as Express middleware / adapter routes before Nest guards, so `@Roles()` does not apply. The document describes endpoints but exposes no data. No unauthenticated, wrong-role or deactivated-user path to protected data is opened.
- **CSP**: scripts are allowed only with the per-request nonce plus the `cdn.jsdelivr.net` origin; there is no `unsafe-inline` for scripts. `style-src` keeps `'unsafe-inline'` because Scalar injects styles at runtime. The relaxation is scoped to `/api/v1/docs` and does not apply to API routes.
- **Supply chain**: the bundle comes from a CDN URL that is not version-pinned by default. Called out in `design.md` with the pinning option.

## Verification

- Unit gate (`pnpm lint`, `pnpm check`, `pnpm test`) per subtask.
- The E2E harness boots `AppModule` and does not run `main.ts`, so it cannot cover the docs wiring and no E2E suite is added: this is a manual run. Start the app and check with `curl`: `/api/v1/docs` returns 200 HTML whose script tags carry the same nonce as its CSP header; `/api/v1/docs-json` returns the OpenAPI JSON; an API route still returns helmet's default CSP.
- Open `/api/v1/docs` in a browser and confirm Scalar renders with no CSP errors in the console, endpoints are listed, and the Bearer token can be set.
- Run `pnpm test:e2e` once before the PR to confirm nothing else regressed.
